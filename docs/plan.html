Nima, built on open source

AI stylist, virtual try-on, social fashion feed and marketplace, Kenya-first (KSh, M-Pesa, Pick Up Mtaani). One Expo app for iOS, Android and a responsive web. Everything is open source and self-hosted on one Contabo VPS, except try-on images, which use Google Gemini the way the original app did.

04Architecture

Everything runs on one VPS. Workers send try-on images to Google Gemini and push the results back over WebSocket.

  • The API never does slow work inline. It queues a job, returns a jobId, and the result arrives over WebSocket.
  • Postgres and Valkey listen only on the internal Docker network, with passwords. Only ports 80/443 and SSH are public.
  • Every AI model or outside service sits behind an interface (TryOnProvider, LLMProvider, PaymentProvider, LogisticsProvider…), so we can swap it without touching the rest of the code.

05Virtual try-on: Gemini, done better

We keep the original app's approach and fix what made it slow, costly and leaky.

How the original app did it

  1. RequestThe user taps try-on. Credits are taken and a pending job is created.
  2. DownloadThe server fetches the user's photo and up to 5 item photos, at full size.
  3. GPT-4oWrites a "photography director" prompt: keep face and body, show every item.
  4. Geminigemini-3-pro-image-preview dresses the person, falling back to Flash when busy, with one retry.
  5. SaveThe image is stored and the app updates.

The same recipe powered item, outfit, camera Quick Try-On, recreate, seller links, the partner API, wardrobe clean-up and ghost mannequin. Why keep it: Gemini handles several items and accessories at once, which dedicated try-on models don't. It's proven on Kenyan outfits and needs no GPU of our own.

What we do better

Cost maths

Estimates. Confirm on Google's pricing page before launch.

ItemPer imageNotes

One credit soldKES 50 ≈ $0.39iOS nets 15–30% less after Apple's cut

Free credits are the real cost

Paid try-ons are profitable, since a credit covers even a Pro image about 3×. But 5 free try-ons a week costs ≈ $0.25–0.65 per active free user, so 1,000 active free users ≈ $1,100–2,800/month in the worst case. That's why the free grant starts at 5, not 20. Watch it and tune it.

Privacy: user photos go to Google. Say so at upload and in the privacy policy, and use the paid API tier.

How a try-on runs in the new app

  1. RequestThe user picks items and a photo; the app calls POST /tryon.
  2. Check + chargePhoto check, then credits debited and job queued in one transaction.
  3. GeminiA VPS worker resizes the images, builds the prompt and calls Flash or Pro.
  4. DeliverResult stored privately; tryon.done over WebSocket. Refund on failure.
  5. Notice"Visualization only — check the seller's size guide."

Accessories (jewellery, sunglasses) use the upper-body photo in the same pipeline, labelled "beta" at first.

Making a CPU model feel fast

The model only works out what the user wants ("wedding, elegant, under KSh 5,000, size M"). Our code runs the search and returns real, in-stock products. The model then writes a short reply that streams word by word. Short prompts plus llama.cpp's prompt cache avoid long waits before the first word. If it still feels slow, a cheap hosted model (e.g. Gemini Flash text) can be swapped in.

VPS size: aim for 12+ vCPU and 48 GB+ RAM. The minimum is 8 vCPU / 32 GB with the smaller 4B model.

10Key flows

Guest → account
Open app as a guest → browse, like and add to cart → a gated action opens the sheet: "Create an account to try this look on yourself." → the guest's data merges into the new account → the questionnaire is an optional card and never blocks
Ask Nima
The model works out intent and filters → tools run the search, wardrobe, style profile, matching items, look creation and try-on → only real, in-stock items → the reply streams
Wardrobe
Upload → BiRefNet cut-out → Qwen-VL tags → FashionSigLIP vector → appears in Wardrobe
For You
Candidates from taste match, follows, trending, seasonal sets and labelled promotions → weighted score, lowered by "not for me" and skips → the taste vector keeps learning from activity
Checkout
Cart split per store → choose a Pick Up Mtaani point → Fingo M-Pesa prompt → verified webhook marks the order paid and credits the seller's ledger → seller marks ready and a parcel is created → after collection and the return window, the seller is paid
Seller photos
Upload → BiRefNet white background (free) → optional Gemini ghost mannequin (seller credits) → seller picks an image

Legal check needed

Fingo can't split one payment between sellers, so Nima holds the money until delivery. That may raise Central Bank of Kenya licensing questions.

13VPS & ops

  • Services: caddy, api, worker, ml-cpu, llm (llama.cpp), postgres, valkey, garage, imgproxy, stalwart, glitchtip, uptime-kuma.
  • Backups: nightly database dump plus continuous WAL archiving, and a Garage snapshot, copied offsite. Test a restore monthly.
  • Security: firewall allowing only web and SSH; fail2ban; SSH keys only; non-root containers; secrets kept out of git; the database never public.

How their try-on worked

No dedicated try-on model. GPT-4o wrote a "photography director" prompt, then Google Gemini (gemini-3-pro-image-preview) got the user's photo plus up to 5 item photos with the instruction to keep the face and body and dress them in every item. It retried once if the result was empty. The same recipe powered item, outfit, camera Quick Try-On, recreate, seller links and the partner API, plus wardrobe cleanup and ghost mannequin. All of it was paid. We keep Gemini for images, drop the GPT-4o step and OpenAI entirely, and add the improvements in section 05.

16Open questions

  1. Brand colours: the Canva design (brown #4A2A12 / cream / terracotta) or the old app (burgundy #5C2A33 / ivory / rose gold)?
  2. Existing users: shopnima.ai and the old backend look live. Move their users, products and looks into the new database, or start fresh? Keep the shopnima.ai domain?
  3. Contabo plan specs (vCPU / RAM / disk). These decide which chat model size we can run.
  4. Fingo: is there a card API? Can they split settlement so we avoid holding funds? What are the fees?
  5. Pick Up Mtaani API key: request it via their support email; it needs a registered business.
  6. Platform fee percentage, and the return window before sellers are paid.
  7. Old features: keep Nima Connect, Nima Wrapped, the tailor portal and seller try-on links on the roadmap?
  8. Kenya Data Protection Act: consent for body photos, deletion, registration; rewrite the privacy policy and terms.
  9. iOS credit prices: charge more on iPhone to cover Apple's cut, or absorb it?
  10. Ask Nima chat: free on our VPS (slower, ≈ 5–10 words/s), or a cheap hosted model like Gemini Flash (fast, pennies per chat)?
  11. Google account: can we reuse the old Gemini API key and billing account?
